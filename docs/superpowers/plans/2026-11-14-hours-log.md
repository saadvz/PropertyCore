# Hours Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build each property's monthly hours log from the records Property Core already keeps, let the host confirm it in chat, and hand it to the host's agent for their Google Sheet.

**Architecture:** A pure builder in `src/hours-log/` reads the property folder's JSON records and returns rows; nothing in the existing desks changes. A small desk keeps settings and month confirmations in `hours.json` and answers three tools, which the shared service lists behind `HOURS_LOG=1`.

**Tech Stack:** TypeScript (ESM), vitest, zod-free JSON schemas like the other hosted tools.

**Spec:** `docs/superpowers/specs/2026-11-14-hours-log-design.md`

## Global Constraints

- Owner rows only for the host's own actions; anything else is routed away from the owner log in one place (`ownerRules.ts`).
- Owner hours come only from host-set minutes per code; unset is 0.
- Every row has a non-empty `reference`.
- Rows are never stored; `hours.json` holds settings, fingerprints and export marks only.
- Tests use made-up names, 555 numbers and no real door codes (AGENTS.md).
- `npm run typecheck`, `npm run build`, `npm test` stay green.

## Review Focus

- A month with no records at all: review returns empty logs, no crash, and export still works after confirm.
- A Fixer job cancelled after the host's go: the go row stays (the host did approve), no visit row.
- A record in another month (or across midnight in the property's zone): it lands by the local date, not UTC.
- Rows that change after confirm (a late DONE): export refuses until a new review.
- Settings naming an unknown code or field: refused with a plain line, nothing saved.
